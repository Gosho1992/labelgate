# B1/B2 results — does Nano add value inside the real app pipeline? (Nov 25, 2026)

**Setup**
- Same `detect()` code for app and benchmark (`src/detect/pipeline.js`), same frozen dictionary (2026.11.25-1), same frozen prompt (extract-v1), same schema (claims-v1), same span validation and profile code.
- One Nano call per case; the three arms are computed from that one output.
- Machine: AWS m5.xlarge, CPU only (Chrome reports GpuBlocked), Chrome 158, Gemma 4 for Built-in AI flag on. Transport: Chrome Prompt API (Firebase AI Logic transport is Phase E).
- Raw results: `bench/results/b2-app-pipeline-2026-11-25.json` (all 90 rows incl. raw model output). Earlier go/no-go v1 results are untouched in `labelgate/GONOGO-RESULTS-2026-11-25.md`.
- Rules arm is deterministic and was recomputed in Node: identical to the browser on every case.

## Headline (held-out v2, 20 new cases × 3 repeats = 60 runs)
| Arm | Precision | Recall | Silent misses | False positives | Review rate |
|---|---|---|---|---|---|
| Rules only | 0.33 | 0.19 | 39 | 18 | 0.05 |
| Nano only | 0.43 | 0.50 | 0 | 32 | 0.97 |
| Hybrid (app) | 0.39 | 0.56 | 0 | 42 | 0.98 |

Latency (CPU): p50 13.8 s, p90 18.4 s, max 54.4 s per spec.

**Honest reading**
1. **Recall goes up (0.19 → 0.56), but "0 silent misses" is not a real win yet.** Nano flagged 97% of all specs for review because it copies the prompt's example words ("lecithin, emulsifier, natural flavour") into `unresolved` even when they are not in the text (58/60 v2 runs, 19/20 legacy runs). When everything is flagged, nothing is silent — but a reviewer gets no signal.
   - *Diagnostic only, not a result:* if a Nano note counted only when its words appear in the spec, hybrid would have **13** silent misses vs **39** for rules, at a 0.48 review rate.
2. **Nano finds the risky ingredient more often than it names the right allergen.** For the 13 unseen terms (39 runs): right allergen 18 (46%), right ingredient but wrong allergen 13 (33%), missed 8 (21%).
   - Consistent errors: Glycine max → wheat (should be soy), ovomucoid → milk (egg), monkey nut → treenut (peanut), krill → fish (shellfish).
   - Always missed: kamaboko, Corylus avellana.
   - Span validation cannot catch these, because the quoted words do exist in the text; only the allergen label is wrong.
3. **Precision is low.** Hybrid has 42 false positives on 60 runs. 18 of 42 come from dictionary look-alikes ("coconut milk", "sunflower seed butter", "cream of tartar", "soy-free tamari", the precaution phrase in H28); the rest are Nano mislabels (wheat for soy, milk for egg, etc.).
4. **Nano never left a gold-review case unflagged** (9/9), but that is mostly the echo effect from point 1.
5. **v2 was built to stress the dictionary** (unseen wording by design). Rules recall 0.19 is NOT an estimate of real-world rules recall; the real mix of familiar vs unfamiliar wording is unknown.

**Conclusion:** Nano adds measurable recall on unfamiliar wording inside the real app (+6 of 16 allergens per run on average). In the current form it is not trustworthy as a classifier: it often names the wrong allergen, and its review flags are mostly noise.

**Two pipeline fixes follow from this (not done; waiting for your review):**
- **(a)** Validate Nano `unresolved` notes against the text, the same way claims are validated.
- **(b)** Treat a Nano-only find as "possible allergen in <ingredient> — confirm which" instead of a confirmed allergen class.

Both need a fresh held-out set (v3) to measure, because v2 has now been seen.
